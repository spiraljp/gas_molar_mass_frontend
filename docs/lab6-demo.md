# Показ лабораторной 6

Это сценарий для реальных снимков экрана. Ответы тестового адаптера не являются доказательством работы БД или MinIO.

Перед показом: подготовьте существующего пользователя, запустите frontend (`npm run dev`), откройте DevTools. Для серверных сценариев нужны FastAPI, PostgreSQL, Redis и MinIO из backend-проекта. Не публикуйте снимки с действующим session_id.

| № | Что снять |
|---|---|
| 1 | При выключенном FastAPI: плитка `#/catalog`, сообщение о демонстрационных данных, поиск по названию. |
| 2 | Лента `#/feed` с mock, переключение газов работает. |
| 3 | После запуска FastAPI: каталог, Network → ответ `/api/gases`, данные из сервиса. |
| 4 | Лента с серверным газом, переход «Следующий газ» вызывает `/api/gases/feed`. |
| 5 | Страница входа `#/login`; показать авторизацию через сервер. |
| 6 | После входа: `#/create`, создание черновика с изображением и видео, масса/плотность, публикация. |
| 7 | В клиенте БД измените название собственного опубликованного газа; снимок изменения в БД. |
| 8 | Обновите плитку: новое название пришло с сервера. При необходимости очистите фильтр. |
| 9 | Выполните вход, покажите Redux `auth.user`; нажмите F5 — Redux снова гость, Application → Cookies → `session_id` осталась. |
| 10 | В Postman/Insomnia выполните GET `http://127.0.0.1:8000/api/gases`, передайте заголовок `Cookie: session_id=<значение из Application>`. Покажите `is_owner: 1` собственного газа. |
| 11 | `src/store/authSlice.ts`, `src/store/gasesSlice.ts`, Redux DevTools: auth, фильтр, данные, pending/error/source. |
| 12 | `scripts/generate-api.mjs`: `httpClientType: 'axios'`; `src/api/generated/Api.ts`: импорт Axios, HttpClient. |
| 13 | `fetchGases` и `fetchGasFeed` в `gasesSlice.ts`, вызовы сгенерированных методов. |
| 14 | `createGas`, `publishGas`, `deleteGas`, `toggleGasLike`: предметные имена thunk и вызовы клиента. |
| 15 | Network: адрес браузера `http://localhost:5173/api/gases?search=...` (порт смотрите в Vite), конфигурация `/api` proxy. |
| 16 | После загрузки своих файлов: API возвращает `http://localhost:9000/gas-media/<имя>`, браузер загружает `/s3/gas-media/<то же имя>`. Покажите второй маршрут proxy и объект в MinIO. |

Для пункта 7 используйте реальные столбцы backend-модели `gases`: например `UPDATE gases SET gas_name = 'Азот — обновлено' WHERE id = <id собственного газа>;` и commit. Frontend не меняет БД напрямую. Этот запрос вручную выполняется в вашей БД на выбранной записи.

При входе используется HttpOnly session-cookie: копируйте её в DevTools Application, не через `document.cookie`. После F5 Redux и серверная сессия имеют независимые жизненные циклы. Гостевой интерфейс скрывает удаление даже если cookie ещё передаётся серверу. Повторный вход возвращает пользовательский интерфейс. Выход вызывает серверный logout, очищает cookie и Redux-фильтр.

На сервере список возвращает опубликованные газы всех пользователей с `is_owner`. Если в ответе нет `is_owner: 1`, опубликуйте газ этим пользователем. Для лайков можно показать повторный клик: thunk читает текущее значение с сервера и переключает его. Во время запроса кнопки блокируются индикатором.

## Дополнения по замечаниям ЛР6

1. Меню: снимите каталог гостя с заблокированным пунктом «Добавление», затем тот же экран после входа с доступным пунктом. При загрузке панель остаётся видимой, все её действия блокируются.
2. Поиск: в Network очистите список, введите название — запрос не должен появиться от набора текста. Нажмите «Найти» — появляется `/api/gases?search=...`. Enter выполняет тот же поиск. Для показа кода откройте `CatalogPage.tsx` и `GasFilter.tsx`: таймер отсутствует, запрос привязан к отправке формы.
3. Реверс-прокси: слева покажите `vite.config.ts` с `/api` и `/s3`, справа Network → Headers реального запроса. Request URL должен иметь origin фронтенда, например `http://localhost:5173/api/gases`. Для MinIO покажите `/s3/gas-media/<имя>`.
4. Заголовки бэкенда: отдельным кадром покажите `../labs_backend/main.py` — создание FastAPI и подключение router, без `CORSMiddleware`. Дополните поиском `CORSMiddleware|Access-Control` по исходникам бэкенда и Response Headers запроса. Отсутствие этих заголовков само по себе не доказывает отсутствие исторических правок; если требуется сравнение, используйте Git diff относительно согласованного с преподавателем коммита. При текущей проверке `git -C ../labs_backend status --short` не показал незакоммиченных изменений. Снимки HTTP-заголовков нужно сделать с работающим сервисом.
5. Четыре страницы: плитка, лента, вход, добавление. Отдельная страница подробностей, её маршрут и ссылки удалены. Для кадров 3–6 используйте именно эти четыре страницы.
6. Предпросмотр файлов: на странице добавления выберите изображение и видео. До отправки формы над соответствующими полями появляются фото и видеоплеер. Выберите другие файлы — содержимое предпросмотра обновляется. Снимок делайте до нажатия «Создать черновик», чтобы было видно, что отображаются локально выбранные файлы.

## Контрольные вопросы

- **Redux Toolkit:** UI отправляет action через dispatch → middleware → reducer → новое состояние store → перерисовка подписанного UI. Reducer синхронный; thunk выполняет асинхронный запрос и dispatch действий `pending`, `fulfilled`, `rejected`. `createSlice` использует Immer для безопасного обновления состояния; `configureStore` собирает reducers и включает thunk.
- **Axios:** HTTP-клиент с Promise, настройками baseURL/timeout/headers, query params, JSON и multipart, interceptors. Здесь доменные методы сгенерированы из OpenAPI; auth написан вручную. HttpOnly cookie управляется браузером, не хранится в Redux.
- **localStorage:** синхронное постоянное хранилище строк на origin, доступное JavaScript. JSON нужно сериализовать. В этой работе Redux не восстанавливается из storage; сессия хранится в cookie, поэтому остаётся после F5.
- **CORS:** браузерные ограничения чтения ответа другого origin. Обратный прокси принимает запрос на origin приложения и обращается к другому сервису на серверной стороне. В работе отдельные маршруты для API и S3.
- **BFF:** серверный слой под потребности конкретного frontend, который может агрегировать ответы и скрывать особенности внешних сервисов. Текущий Vite proxy только перенаправляет запросы, не агрегирует их.
- **GraphQL:** API со схемой и выбором полей клиентом; query читает, mutation изменяет данные, resolver получает их. В проекте REST/OpenAPI, GraphQL не используется.
- **Next.js и SSG:** Next.js — React-фреймворк, поддерживающий серверный рендеринг и генерацию страниц. SSG создаёт HTML заранее, обычно при сборке. Здесь Vite SPA: динамические данные запрашиваются в браузере.
- **FSD:** организация frontend по слоям и предметным срезам, с публичным API модулей и направлением зависимостей к нижним слоям. Типичные слои: app, pages, widgets, features, entities, shared. Текущий небольшой проект организован по pages/components/store/api и не заявляет полное соответствие FSD.

Методические материалы: [Redux Toolkit](https://github.com/iu5git/Web/blob/main/tutorials/redux/redux_toolkit.md), [кодогенерация и Axios](https://github.com/iu5git/Web/blob/main/tutorials/lab7/README.md).
