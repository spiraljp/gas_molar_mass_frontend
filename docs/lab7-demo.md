# ЛР7: запуск и скриншоты

## GitHub Pages и PWA

Ветка: `lab7-pwa-https`. Workflow: `.github/workflows/pages.yml`. В репозитории GitHub выберите Settings → Pages → Build and deployment → Source: GitHub Actions. После commit и push этой ветки workflow соберёт `npm run build:pages` и опубликует `dist`.

Ожидаемый адрес после успешной публикации: `https://spiraljp.github.io/gas_molar_mass_frontend/`. До успешного Actions deployment считать публикацию завершённой нельзя. В Pages-сборке `VITE_MOCK_ONLY=true`: гость, локальные mock, без запросов к `/api`. Вход и добавление заблокированы. Пути медиа, manifest и service worker учитывают префикс репозитория.

На iPhone откройте опубликованный адрес в Safari, выберите «Поделиться» → «На экран Домой». Если iOS предлагает «Открывать как веб-приложение», оставьте включённым. Откройте приложение с домашнего экрана. Первая загрузка должна завершиться с доступной сетью. Service worker кеширует HTML/JS/CSS/изображения. Видео не входят в offline-cache из-за размера; для их просмотра оставьте сеть включённой.

## Локальный HTTPS: iPhone + Windows/WSL

1. Подключите ноутбук и iPhone к одной Wi-Fi сети без изоляции клиентов. Запустите контейнеры и FastAPI из `labs_backend`. Backend остаётся на `127.0.0.1:8000`, MinIO — `127.0.0.1:9000`, доступ к ним с телефона идёт через Vite proxy.
2. В Windows PowerShell выполните `ipconfig`, найдите IPv4 Wi-Fi адаптера. Текущий Wi-Fi IP ноутбука: `192.168.0.188`; при смене сети замените его актуальным. Не используйте внутренний IP WSL для адреса в Safari.
3. В WSL из папки frontend:

   ```bash
   npm run cert:generate -- 192.168.0.188
   npm run dev:https
   ```

   Остановите предыдущий `npm run dev`, если порт 5173 занят. Скрипт сертификата создаёт локальный корневой CA и подписанный сертификат сервера с IP в Subject Alternative Name. При изменении Wi-Fi IP повторите генерацию с новым адресом. CA переиспользуется, если его файлы сохранены. Ключи и сертификаты в `.certs/` исключены из Git и из `dist`.
4. Для стандартного WSL2 NAT в **Windows PowerShell от администратора** запустите скрипт проекта:

   ```powershell
   Set-Location "\\wsl.localhost\Ubuntu\home\spiral\Kostylev_5SEM_26\gas_molar_mass_frontend"
   .\scripts\wsl-lan.ps1
   ```

   Замените `Ubuntu` на имя своей WSL-дистрибуции (`wsl -l -q`), либо откройте PowerShell в каталоге проекта. Скрипт перенаправляет Windows TCP 5173 в WSL TCP 5173 и разрешает этот порт для локальной подсети в Private-профиле Windows Firewall. Сеть Wi-Fi должна иметь профиль «Частная». После перезапуска WSL его IP может измениться — повторите скрипт. В mirrored-режиме WSL portproxy может не понадобиться; проверьте доступ по LAN и правила Hyper-V firewall отдельно.
5. Передайте на iPhone **только** `.certs/gas-catalog-ca.cer` (например, через приложение Files/iCloud Drive или почту), откройте его и установите профиль в настройках. Приватные ключи `*-key.pem` передавать нельзя. После установки включите доверие: «Настройки → Основные → Об этом устройстве → Доверие сертификатам → Gas Catalog Local CA». Одной установки профиля без включения доверия недостаточно.
6. Откройте в Safari `https://192.168.0.188:5173/`. Не должно быть предупреждения о недоверенном сертификате. Войдите, проверьте каталог, ленту и добавление. Все обращения к API и MinIO остаются на HTTPS origin Vite. Бэкенду не нужно открывать порт 8000 наружу или менять CORS.
7. Для HTTPS без предупреждения в Windows установите этот же CA в «Доверенные корневые центры сертификации» текущего пользователя. Проверка сертификата:

   ```bash
   openssl x509 -in .certs/localhost.pem -noout -issuer -dates -ext subjectAltName
   openssl verify -CAfile .certs/ca.pem .certs/localhost.pem
   ```

При тестировании по IP в `npm run dev:https` SW не устанавливается. Это локальный сценарий работы с сервером; установку PWA показывайте с опубликованного GitHub Pages. Для production-проверки PWA локально можно использовать `npm run build`, затем `npm run preview:https` (порт 4173; для телефона потребуется соответствующий portproxy).

## Краткие контрольные вопросы

- **Flux:** однонаправленный поток: действие пользователя → action/dispatch → изменение store → обновление UI. Это архитектурная идея; Redux реализует однонаправленный поток с reducers.
- **Redux:** store хранит состояние, action описывает событие, dispatch отправляет его, reducer вычисляет новое состояние. Middleware обрабатывает действия между dispatch и reducer; thunk нужен для асинхронных операций.
- **PWA:** веб-приложение с manifest и service worker, которое можно установить и открыть в standalone-режиме. Остаётся веб-приложением; поддержка системных возможностей зависит от браузера и ОС.
- **Нативное приложение:** использует платформенные API/SDK; устанавливается как приложение ОС. Кроссплатформенные варианты: React Native/Flutter с собственным UI-стеком; Tauri — приложение с системным WebView и нативной частью; Electron — desktop с Chromium и Node.js. Это разные подходы, PWA не равно нативному приложению.
- **GitHub Pages:** HTTPS-хостинг статических файлов. В этой работе размещает сборку React и mock. FastAPI, PostgreSQL, Redis и MinIO на Pages не запускаются.
- **HTTPS:** HTTP поверх TLS, шифрование соединения и проверка сервера по сертификату. SAN сертификата должен содержать IP из адресной строки, а клиент должен доверять выдавшему CA.
